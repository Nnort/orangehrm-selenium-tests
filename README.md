# Автотесты авторизации OrangeHRM

UI-тесты сценариев входа и выхода на демо-стенде OrangeHRM.
Selenium WebDriver + pytest, паттерн Page Object.

**Тестируемое приложение:** https://opensource-demo.orangehrmlive.com/

**Стек:** Python 3.13, pytest, Selenium 4, pytest-html
## Установка

Требуется Python 3.10+ и установленный Google Chrome.

```bash
git clone https://github.com/Nnort/orangehrm-selenium-tests.git
cd orangehrm-selenium-tests
```
Создание окружения:
```bash
python -m venv .venv
```
Активация - Windows:
```bash
.venv\Scripts\activate
```
Активация - macOS / Linux:
```bash
source .venv/bin/activate      # macOS / Linux
```
Установка зависимостей:
```bash
pip install -r requirements.txt
```

Драйвер Chrome разрешается автоматически через Selenium Manager
(встроен в Selenium 4.6+), устанавливать chromedriver вручную не нужно.

## Запуск

```bash
python -m pytest -v                                       # все тесты
python -m pytest tests/test_login.py::test_logout -v      # отдельный тест
python -m pytest --html=reports/report.html --self-contained-html   # с отчётом
```

Отчёт последнего прогона: `test-report.html` - Для запуска необходимо скачать файл и открыть локально в браузере

## Структура проекта

```
orangehrm-selenium-tests/
├── conftest.py              # фикстура драйвера, корень импорта проекта
├── config/
│   └── settings.py          # адрес стенда, учётные данные, таймаут
├── pages/
│   ├── base_page.py         # общие действия: click, fill, text_of, is_visible
│   ├── login_page.py        # страница входа
│   └── dashboard_page.py    # страница авторизованного пользователя
├── tests/
│   └── test_login.py        # сценарии входа и выхода
├── requirements.txt
├── pytest.ini
└── test-report.html         # отчёт о прогоне
```

Разделение по слоям:

- **tests** - сценарии и проверки. Не содержат селекторов и не работают
  с Selenium напрямую;
- **pages** - взаимодействие со страницами: локаторы и действия.
  Не содержат `assert` - проверка остаётся ответственностью теста;
- **config** - параметры окружения, вынесенные из кода;
- **conftest.py** - жизненный цикл драйвера. Расположен в корне, так как
  задаёт корень импорта для пакетов `pages` и `config`.

## Документация тестов

Реализованы четыре теста, покрывающие сценарий из задания.

### test_main_page_opens
**Проверяет:** стартовая страница загружается корректно.

**Шаги:** 
1. открыть базовый адрес приложения.

**Ожидаемый результат:** заголовок содержит `OrangeHRM`, произошёл
редирект на `/auth/login`, поле ввода логина отображается.

### test_login_with_invalid_credentials_shows_error
**Проверяет:** при вводе неверных данных отображается ошибка.

**Шаги:** 
1. Открыть базовый адрес приложения.
2. Заполнить поле Username значением "test"
3. Заполнить поле Password значением "test"
4. Нажать на кнопку "Login"

**Ожидаемый результат:** Появляется бейдж с ошибкой `Invalid credentials`, вход не выполнен - редиректа на дашборд не происходит

### test_login_with_valid_credentials_success
**Проверяет:** при вводе верных данных происходит успешная авторизация.

**Шаги:** 
1. Открыть базовый адрес приложения.
2. Заполнить поле Username значением `Admin`
3. Заполнить поле Password значением `admin123`
4. Нажать на кнопку `Login`

**Ожидаемый результат:** произошёл редирект на `/dashboard/index`

### test_logout
**Проверяет:** При выходе из системы сессия завершается, происходит редирект на страницу входа `/auth/login`

**Шаги:** 
1. Открыть базовый адрес приложения.
2. Заполнить поле Username значением `Admin`
3. Заполнить поле Password значением `admin123`
4. Нажать на кнопку `Login`
5. Нажать меню личного профиля в правом верхнем углу страницы
6. Нажать на ссылку `Logout`

**Ожидаемый результат:** сессия завершена, произошёл редирект на `/auth/login`, прямой доступ к дашборду недоступен

## Предположения и ограничения

### Выбор тестируемого приложения

Первоначально рассматривался коммерческий сайт. При обращении браузером
под управлением WebDriver он возвращает HTTP 403 - срабатывает защита
от автоматизации. Обход ограничения не применялся: это противоречит условиям
использования и делает тесты нестабильными. Выбран публичный демо-стенд,
предназначенный для открытого доступа.

### Предположения

- В качестве тестируемого приложения выбран официальный публичный демо-стенд
  OrangeHRM. Учётные данные размещены на странице входа самим разработчиком,
  что позволяет использовать их в открытом репозитории.
- Приложение не имеет отдельной публичной главной страницы: неавторизованный
  пользователь перенаправляется на `/auth/login`. Шаг задания «найти и кликнуть
  ссылку Вход» реализован как проверка этого редиректа. «Главная страница»
  после авторизации интерпретирована как `/dashboard/index`.
- Приложение не защищено капчей и не блокирует учётную запись после серии
  неудачных попыток входа.
- Тесты не изменяют состояние приложения (только чтение), поэтому очистка
  данных после прогона не требуется.

### Ограничения

- **Общий демо-стенд.** Данные доступны всем пользователям и периодически
  сбрасываются. Тесты сознательно не опираются на конкретные записи в системе.
  Падение теста может означать недоступность стенда, а не дефект приложения.
- **Один браузер.** Проверено только в Chrome. Кросс-браузерный запуск
  не реализован.
- **Headless-режим не реализован** - тесты выполняются в видимом браузере.
  Для запуска в CI потребуется добавить соответствующие опции в фикстуру драйвера.
- **Изоляция вместо скорости.** Драйвер создаётся заново на каждый тест
  (`scope="function"`). На текущем объёме экономия времени не оправдывает
  связанность тестов через общее состояние браузера.
- **Проверка «корректного отображения» сведена к явным критериям:** заголовок
  документа, URL и наличие ключевых элементов. Визуальное соответствие макету
  и вёрстка не проверяются.
